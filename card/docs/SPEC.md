# SPEC.md — 野兽牌 设计文档

> 邪恶冥刻风格策略卡牌对战 · Web 应用

---

## 1. 问题陈述

### 要解决什么问题？

目前市面上缺少一款以《邪恶冥刻》（Inscryption）为原型的、支持多人在线对战的卡牌策略游戏。本项目实现一个完整的 Web 端卡牌对战平台——**野兽牌**，包含用户注册登录、卡牌收集与卡组构建、人机对战、玩家对战、好友社交等核心功能。

### 目标用户

- 喜欢《邪恶冥刻》等 Roguelike 卡牌游戏的玩家
- 希望在线与好友或随机对手进行策略卡牌对战的用户
- 对卡牌构筑和印记组合策略感兴趣的玩家

### 为什么值得做？

- 邪恶冥刻的核心战斗机制（献祭、印记、骨头经济）在 Web 端尚无完整实现
- 支持 PvP 实时对战 + 好友系统，具有社交粘性
- 68 张卡牌 × 35 种印记 × 5 种族，提供丰富的策略深度

---

## 2. 用户故事

| # | 角色 | 故事 | 验收标准 |
|---|------|------|----------|
| US-1 | 新玩家 | 我想用邮箱注册账号，收到验证码后完成注册，获得一个唯一ID（如张三#138992） | 注册成功返回完整标识；邮箱不可重复；验证码 10 分钟有效 |
| US-2 | 玩家 | 我想在商店浏览并购买卡牌，用金币扩充我的收藏 | 购买后金币扣除；卡牌解锁加入收藏；库存正确更新 |
| US-3 | 玩家 | 我想选择一个人物并组建符合要求的卡组（数量匹配、传奇≤3、重复不超限），最多20个卡组 | 卡组校验不通过时阻止进入游戏并提示原因 |
| US-4 | 玩家 | 我想进行人机对战，体验完整的献祭→出牌→攻击回合流程 | 4v4 棋盘；回合操作连贯；投降或血量归零时结束 |
| US-5 | 玩家 | 我想和在线的其他玩家实时 PvP 对战，每回合 30 秒时限 | 匹配成功后实时对战；超时自动结束回合；胜负影响积分 |
| US-6 | 玩家 | 我想添加好友、查看好友的卡牌数据和战绩、私信聊天、发起对局邀请 | 通过 ID 搜索好友；可查看对方数据；私信实时送达 |

## 3. 功能规约

### 3.1 认证模块

| 功能 | 输入 | 行为 | 输出 | 边界/错误 |
|------|------|------|------|-----------|
| 发送验证码 | 邮箱 | 生成6位验证码 → 发送邮件 → 内存存储(10分钟TTL) | `{message: "验证码已发送"}` | 60秒冷却；邮箱已注册时仍可发送 |
| 注册 | 邮箱+验证码+密码+昵称 | 校验验证码 → 校验邮箱唯一 → BCrypt加密密码 → 生成6位唯一标识 | `{success, fullId}` | 验证码错误/过期；邮箱已注册 |
| 登录 | 邮箱+密码 | 查找用户 → BCrypt校验 → 签发JWT(24h) | `{token, nickname, uniqueTag, gold, points}` | 邮箱或密码错误返回401 |
| 登出 | JWT | 前端清除Token（服务端无状态） | `{message: "登出成功"}` | — |

### 3.2 卡牌模块

| 功能 | 说明 |
|------|------|
| 卡牌属性 | name, health(血量), attack(攻击力/特殊), bloodCost(血献祭), boneCost(骨献祭), sigils(印记列表), races(种族列表), maxDeckCount, isLegendary, canShuffle, canSacrifice |
| 印记系统 | 35种印记，可在打出时赋予或固有，支持多印记叠加 |
| 种族系统 | 5种族（狼/爬行/虫/鹿/鸟），可多种族（融合兽） |
| 献祭类型 | 血献祭（献祭己方卡牌，数量精确匹配）/ 骨头献祭（扣除骨头数量） |

### 3.3 商店模块

| 功能 | 说明 |
|------|------|
| 卡牌解锁制 | 购买一次即可无限编入卡组，非消耗品 |
| 统一售价 | 所有卡牌统一价格（由 GameConstants 配置） |
| 战斗奖励 | PvE 胜利奖励金币，用于商店消费 |

### 3.4 卡组模块

| 规则 | 说明 |
|------|------|
| 数量匹配 | 卡组卡牌数量 = 人物要求的卡组数量（10-20） |
| 传奇限制 | 牌组中传奇卡 ≤ 3 张 |
| 重复限制 | 每张卡牌数量 ≤ 该卡的 maxDeckCount |
| 卡组上限 | 每用户最多 20 个卡组 |
| 不可入组 | maxDeckCount=0 的卡牌（松鼠/兔子/蜜蜂等）不能选入牌组 |
| 拥有校验 | 只能将已购买的卡牌编入卡组 |
| 操作 | 创建/编辑（点击卡牌图片添加）/重命名/删除 |

### 3.5 对战模块

| 阶段 | 说明 |
|------|------|
| 对战前准备 | 选人物 → 选关卡 → 选卡组 → 进入游戏 |
| 开局 | 随机先后手；初始抽5张；若卡组有1费血献祭卡则保底1张 |
| 每回合操作 | 抽牌(松鼠/牌组) → 选牌 → 献祭 → 出牌(可多次) → 结束回合 → 自动攻击 |
| 攻击逻辑 | 默认攻击对位卡牌；对位无卡牌则攻击敌方人物；印记可修改目标 |
| 胜负判定 | 一方投降 或 人物血量≤0 时结束 |
| PvP特殊 | 30秒回合时限；超时强制结束并回退未完成操作 |

### 3.6 洗牌逻辑

- 被献祭/死亡的己方卡牌进入抽牌堆（无论是否初始牌组中的）
- **永久死亡**（canShuffle=false）：松鼠、蜜蜂、兔子、尾巴、破碎的蛋、铃铛、堤坝
- 牌组已空时，将不在牌桌上的所有牌重新洗进抽牌堆（不含松鼠）

### 3.7 好友模块

| 功能 | 说明 |
|------|------|
| 搜索添加 | 通过唯一标识搜索（如搜索 #138992）；PvP对战中可申请好友 |
| 查看数据 | 查看好友的卡牌使用率/胜率统计和最近20场对战记录 |
| 私信聊天 | 基于 WebSocket 的实时私信 |
| 对局邀请 | 向好友发起 PvP 对局邀请 |

### 3.8 统计模块

| 指标 | 说明 |
|------|------|
| 卡牌使用率 | 每张卡出现在卡组中的次数占比 |
| PvP胜率 | 仅计算玩家对战（不含人机），百分比保留两位小数 |
| 对战记录 | 保存最近20场，记录双方人物和卡组，不记录对局过程 |

## 4. 非功能性需求

### 4.1 性能
- API 响应时间 < 500ms（常规操作）
- PvP 对战消息延迟 < 200ms（WebSocket）

### 4.2 安全
- **凭据威胁模型**：JWT Secret、邮件密码、数据库密码为敏感凭据
- 凭据通过环境变量注入（`${JWT_SECRET}`），绝不硬编码或提交仓库
- 密码使用 BCrypt 哈希存储
- `.env` 文件已加入 `.gitignore`
- JWT Token 有效期 24 小时，过期自动失效
- 生产环境 application.yml 中所有敏感字段均为空默认值，必须通过环境变量注入

### 4.3 可用性
- 暗黑主题 UI（与邪恶冥刻风格一致）
- 响应式布局适配桌面端

### 4.4 可观测性
- 关键操作日志（注册/登录/对战结果）
- Spring Boot Actuator（生产环境可启用）

## 7. 凭据与分发设计

### 凭据管理
- JWT Secret → 环境变量 `JWT_SECRET`
- 邮件密码 → 环境变量 `MAIL_PASSWORD`
- 数据库密码 → 环境变量 `DB_PASSWORD`
- 所有凭据通过 `.env` 文件本地开发使用，已加入 `.gitignore`
- application.yml 中敏感字段默认值为空或占位符，生产必须通过环境变量注入
- 凭据威胁模型：JWT Secret 泄露可伪造 Token；DB 密码泄露可访问全部数据；邮件密码泄露可发送钓鱼邮件

### 凭据录入流程
1. 克隆仓库后创建 `.env` 文件
2. 填入 JWT_SECRET、DB_PASSWORD、MAIL_PASSWORD 等
3. 运行 `docker-compose up -d` 或 `mvn spring-boot:run` 时自动加载

### 分发方式
- **容器分发**：Dockerfile（多阶段构建）+ docker-compose.yml，三条命令启动
- **原生启动**：JDK 21 + Node.js 20，通过 Makefile 一键构建
- **WebUI**：前端 Nginx 生产服务，反向代理后端 API 和 WebSocket

## 10. 风险与未决问题

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| AI 出牌逻辑复杂度 | 可能影响人机对战体验 | 分阶段实现（简单→中等→困难） |
| PvP 并发匹配 | WebSocket 连接管理复杂 | 先用简单轮询，后续优化 |
| 验证码依赖外部 SMTP | 开发环境无法真实发送 | 开发环境打印验证码到日志 |
| 印记交互逻辑复杂（35种） | 实现和测试工作量大 | 分批实现，优先核心印记 |
| 战斗状态管理 | GameSession 内存状态可能丢失 | 关键节点持久化到数据库 |

| 不可入组 | maxDeckCount=0 的卡牌（松鼠/兔子/蜜蜂等）不能选入牌组 |

### 3.4 对战模块

| 阶段 | 说明 |
|------|------|
| 对战前准备 | 选人物 → 组建卡组 → 选关卡 → 进入游戏 |
| 开局 | 随机先后手；初始抽5张；若卡组有1费血献祭卡则保底1张 |
| 每回合操作 | 抽牌(松鼠/牌组) → 选牌 → 献祭 → 出牌(可多次) → 结束回合 → 自动攻击 |
| 攻击逻辑 | 默认攻击对位卡牌；对位无卡牌则攻击敌方人物；印记可修改目标 |
| 胜负判定 | 一方投降 或 人物血量≤0 时结束 |
| PvP特殊 | 30秒回合时限；超时强制结束并回退未完成操作 |

### 3.5 洗牌逻辑

- 被献祭/死亡的己方卡牌进入抽牌堆（无论是否初始牌组中的）
- **永久死亡**（canShuffle=false）：松鼠、蜜蜂、兔子、尾巴、破碎的蛋、铃铛、堤坝
- 牌组已空时，将不在牌桌上的所有牌重新洗进抽牌堆（不含松鼠）

### 3.6 好友模块

| 功能 | 说明 |
|------|------|
| 搜索添加 | 通过唯一标识搜索（如搜索 #138992）；PvP对战中可申请好友 |
| 查看数据 | 查看好友的卡牌使用率/胜率统计和最近20场对战记录 |
| 私信聊天 | 基于 WebSocket 的实时私信 |
| 对局邀请 | 向好友发起 PvP 对局邀请 |

### 3.7 统计模块

| 指标 | 说明 |
|------|------|
| 卡牌使用率 | 每张卡出现在卡组中的次数占比 |
| PvP胜率 | 仅计算玩家对战（不含人机），百分比保留两位小数 |
| 对战记录 | 保存最近20场，记录双方人物和卡组，不记录对局过程 |

## 4. 非功能性需求

### 4.1 性能
- API 响应时间 < 500ms（常规操作）
- PvP 对战消息延迟 < 200ms（WebSocket）

### 4.2 安全
- **凭据威胁模型**：JWT Secret 和邮件密码为敏感凭据
- 凭据通过环境变量注入（`${JWT_SECRET}`），绝不硬编码或提交仓库
- 密码使用 BCrypt 哈希存储
- `.env` 文件已加入 `.gitignore`
- JWT Token 有效期 24 小时，过期自动失效

### 4.3 可用性
- 暗黑主题 UI（与邪恶冥刻风格一致）
- 响应式布局适配桌面端

### 4.4 可观测性
- 关键操作日志（注册/登录/对战结果）
- Spring Boot Actuator（生产环境可启用）

| 实时通信 | WebSocket | PvP 对战和私信需要 |
| 样式 | SCSS + 暗黑主题 | 与邪恶冥刻风格匹配 |

## 10. 风险与未决问题

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 具体卡牌实体和人物设计尚未最终确定 | 后续可能需要调整 Card 字段 | 预留 description/imageUrl 扩展字段 |
| AI 出牌逻辑复杂度 | 可能影响人机对战体验 | 分阶段实现（简单→中等→困难） |
| PvP 并发匹配 | WebSocket 连接管理复杂 | 先用简单轮询，后续优化 |
| 验证码依赖外部 SMTP | 开发环境无法真实发送 | 使用 MailHog 模拟 |
| 印记交互逻辑复杂（35种） | 实现和测试工作量大 | 分批实现，优先核心印记 |
